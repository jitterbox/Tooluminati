Tooluminati · Component Spec

WebMcpTroubleshootingPanel

An in-app developer panel that verifies WebMCP setup at a glance — support, registered tools, recent timeline events, environment warnings, and client errors — without opening the Chrome inspector extension.

Package  @tooluminati/diagnostics
Status  Draft v0.1
Surface  Dev-only / read-only

1 · Purpose

Developers integrating Tooluminati need a fast answer to one question: is WebMCP actually wired up and behaving on this page? Today that requires installing and opening Chrome's Model Context Inspector Extension. The panel brings the five signals a developer checks most into the running app itself, as a draggable corner widget.

It is a verification surface, not a replacement for the inspector. It renders only data Tooluminati already collects via the diagnostics tools, applies the same redaction policy, and reads — never mutates — runtime state.

2 · Placement & form factor

  • Docked corner widget, fixed bottom-right, above app chrome (z-index above app, below modals it does not own).
  • Collapsed badge ⇄ expanded panel. Collapsed shows the brand mark, support state, tool count, and an issue dot. Expanded is a ~412px panel with a scrolling body.
  • Dev-build only. The host tree-shakes it out of production unless explicitly opted in; it never ships to end users by default.

7 · Interactions

  • Collapse / expand — badge ⇄ panel; remembers last state per session.
  • Expandable rows — click any environment check, timeline event, or error to reveal detail + redacted metadata.
  • Category filter — chips scope the timeline; counts update live.
  • Copy diagnostics — serializes all five signals to JSON for bug reports (or onCopyDiagnostics).
  • Refresh — re-runs the environment check and re-reads buffers on demand.

9 · Safety & non-goals

  • Read-only. The panel never calls a mutating tool; it only reads buffers and the environment summary.
  • Same redaction. Query strings, response bodies, and PII are stripped upstream by the diagnostics layer; the panel renders what it is given.
  • Stacks in dev only, mirroring ClientErrorBuffer behavior.
  • Not the full inspector: no live tool execution, no schema browser, no eval runner — those stay in Chrome's extension.
